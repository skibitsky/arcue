# Arcue

Arcue is a desktop app for reviewing 3D models and animations and handing anchored feedback to AI coding agents. You pin or paint on the model at a frame, write a line, and Arcue copies a prompt with the vertices, bones, frame, camera and screenshots. It is an Electron app in TypeScript; a web host runs the same UI, 3D view and core in a browser.

## Packages

| Package | Owns |
|---|---|
| `packages/scene` | The format-independent scene description, anchors, ranges, topology fingerprint, closest-point queries, `Importer`. |
| `packages/protocol` | zod schemas for commands, queries, events, `review.json` and `round.json`; `CoreClient`; the transport. |
| `packages/import-fbx` | The FBX importer on ufbx compiled to WebAssembly. |
| `packages/blend` | `@arcue/blend`, published to npm: reads `.blend` files directly and samples their actions into clips, with its own output types. |
| `packages/import-blend` | The Blender importer: maps `@arcue/blend`'s output to the scene description. |
| `packages/core` | `Platform`, the command registry, and all review state. |
| `packages/platform-node` | `NodePlatform` on Node's file system, the worker_threads import worker, and the `arcue` socket server, for Node hosts. |
| `packages/viewport` | The 3D view: three.js rendering, tools, picking, screenshots. |
| `packages/ui` | Design tokens and fonts, and the panels, timeline and comment box. |
| `apps/web`, `apps/desktop`, `apps/cli`, `apps/plugin` | The browser host, the Electron app, the `arcue` command, the agent plugin for Claude Code and Codex. |

## How it fits together

- The core owns all state. Every action is a command, query or event in `packages/protocol`, handled by the core's registry, and the window, the `arcue` command and any later MCP server all call it through `CoreClient`. Add a feature as a command, never as state in the UI. Commands with `runsIn: "view"` go on to the window that shows the asset, and `internal` commands are refused to bridge callers.
- The core runs in its own process: an Electron utility process on desktop, a Web Worker on the web. It restarts after a crash and windows reconnect, so a window never holds state the core does not have. `arcue serve` runs a core on Node instead of the desktop app and serves its window, built from `apps/web/local`, on localhost; the agent opens it in the built-in browser of the Claude or Codex app.
- Each window and each `arcue` connection gets its own message channel to the core, which answers its requests and sends it every event. The `arcue` socket accepts a caller only with the token from `bridge.json`. `arcue serve` accepts a window only from its own page on a localhost address. Treat every path a bridge caller sends as untrusted: normalize it and keep it inside the folder it belongs to.
- Reviews live in `<git root>/.arcue/reviews/<repo-relative model path>/`, or under the app data folder outside a repository, and Arcue writes `.arcue/.gitignore` with `*` when it creates the folder. The model's path is the key. Renames are followed through the hash, size and Unity GUID that `review.json` records, so change the key only together with `relink.ts` and `review-move.ts`.
- Write `review.json` only through `ReviewSession.run`. Its compute runs again when the file changed on disk, so it must have no side effects: put any other write in `prepare` and undo it in `rollback`.
- Core work is serialized. Take an asset's `compositionEdits` first, then the core's `#opening` or the asset's `loads`, then its session, and never wait on a window or another lock inside a session compute.
- Code in `packages/core` gets time only from `platform.clock`, which tests replace with a manual clock. Never call `Date.now()` or set timers there directly.
- Anchors are source vertex indices, the file's own vertex numbers, with barycentric weights. The importer must keep that numbering: welding or reordering vertices breaks every saved comment. A new version of the file re-anchors comments through the topology fingerprint.
- The ufbx WebAssembly build in `packages/import-fbx/wasm/` is committed. Rebuild it only with `scripts/build-wasm.mjs`, which pins Emscripten and checks the vendored ufbx sources, and never edit its output.
- `packages/blend/vendor/fzstd/` is fzstd 0.1.1's ES module build with the fixes its header lists. Change it only with a test in `blend/decompress.test.ts`, and keep the header's list current.
- The `.blend` fixtures and their reference JSON in `packages/blend/test/fixtures/` are generated by `generate.py` there, in Blender 4.2 and 5.2. Change the script and regenerate; never edit a fixture by hand.
- `packages/blend` is a public package and imports nothing from Arcue; Biome refuses an `@arcue/*` import there. Its source imports carry `.js` extensions for Node. Its `./internal/*` and `./test/*` exports exist only in the workspace, for Arcue's importer tests, and `publishConfig` leaves them out. Publish it through the Publish blend workflow, which runs on a `blend-v<version>` tag and publishes with npm's trusted publishing. Only the first version, which npm needs before it accepts a trusted publisher, is published by hand, with `pnpm publish` from `packages/blend`: `npm publish` ignores `publishConfig` and would publish the TypeScript source.
- `samples/` is generated by `tools/samples/generate.py` in Blender. Change the script and regenerate; never edit a sample by hand.
- `skills/arcue` is the agent skill, in the Agent Skills format that Claude Code and Codex both read. `apps/plugin` builds the plugin and its marketplace from it and the command line, and the Publish plugin workflow commits them to the `plugin` branch; never edit that branch. `.claude-plugin/marketplace.json` on `main` installs the plugin from that branch for hosts that read only the default branch, and a test keeps it equal to `mainMarketplaceManifest` in `apps/plugin`. Keep the skill short and about Arcue, and update it with any change to the command line, `round.json` or composition files. Tests check its commands and format.
- `apps/plugin/launcher` holds the launchers that run the plugin's command line on Node 24 or later from PATH or on the Node that `arcue setup` downloads, with their tests: `arcue` in POSIX sh for macOS, Linux and Git Bash, and `arcue-node.cmd`, which the plugin also ships as `arcue-setup.cmd`, for PowerShell. The `.cmd` file never reads its arguments, and nothing passes arguments through cmd.exe. `node-sha256sums.txt` pins that Node: change it only with `pnpm --filter @arcue/plugin pin-node <version>`, never by hand.

## Rules

- Dependencies point one way: apps import packages, never the reverse. Only `core` reads or writes files, and only through `Platform`. `viewport` and `ui` never import `core`; they use `CoreClient`.
- The schemas in `packages/protocol` are the contract. Change a command, file format or event there first.
- Clips are identified by their name in the file, such as "Armature|Charge", made unique by `clipNames`; a composition's other files prefix theirs as `<file>//<clip>`. Display names are only for people.
- A model's composition file, `composition.json` in its review folder, loads other files into its view. Its paths are relative to the model's folder. Their nodes, parts and anchors are named `<file>//<node path>`; `splitMemberPath` splits them. The core never writes beside the model.
- A `review.json` that an earlier build wrote must keep loading, so new fields are optional or have defaults. Comment ids are `c` and a lowercase ULID, or `c` and a number in older reviews. Never read order or a number from an id: sort by `createdAt`, then id, and number comments by their place in the queue.
- Every package exports its public surface from `src/index.ts`. Do not import another package's internal files.
- Logic gets Vitest tests next to the code, as `*.test.ts`.
- No code comments unless they are essential for understanding how to use the code. Prefer clear names.
- No `any`. TypeScript is strict, with `noUncheckedIndexedAccess`.
- Keep the UI quiet: an outline, timeline, warning or panel appears only when the model needs it. Use sentence case and few words, never uppercase. A trash icon deletes or dismisses; a cross only closes.
- Colors have functions, and each function owns its color: feedback is orange, sent comments a brick, resolved comments olive, the playhead a thin red line, warnings and errors sand, everything else warm charcoal neutrals. Use the tokens in `packages/ui/src/tokens.css`, which take their colors from its palette, never raw colors.
- Verify UI changes in the web host in a browser before calling them done. `?sample=stone-striker&clip=StoneResonatorRig%7CWalk&frame=12` opens a sample at a clip and frame; `window.arcue.client` runs any command or query, `window.arcue.store` holds the window's state, `window.arcue.writeComposition(model, text)` writes a model's composition file, and `window.arcue.renameFile(from, to)` renames a file.
- On Linux without a display, run the desktop app and its tests under `xvfb-run -a`. Without a GPU, start the app with `--use-angle=swiftshader --enable-unsafe-swiftshader` so the 3D view renders.
