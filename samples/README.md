# Sample FBX files

Small FBX files for Arcue's importer tests and for demo models in the web preview.
A script in this repository builds every model from primitives in Blender, so the files carry no
third-party content.

## Files

| File | What it tests |
| --- | --- |
| `crate.fbx` | A static prop. One beveled 1 m mesh with two materials (Wood, Metal), UVs, hard edges, and no textures. |
| `pebble-golem.fbx` | A skinned creature, 1.6 m tall. One fused stone mesh with two materials, 27 deform bones (fingers and a thumb on both hands), automatic weights. Four takes at 30 fps with a key on every frame: Idle (60 frames), Walk (30, loops), Wave (45, right arm), Hit (15). |
| `pebble-golem-sparse.fbx` | The same creature and clips exported with key simplification. Curves have between 2 keys and a key on every frame, for testing key ticks on the timeline. |
| `blob.fbx` | Shape keys. One mesh with Squash and Blink shape keys and one 30-frame take, `Bounce`, that animates them. |
| `textured-rock.fbx` | An embedded texture. A rock with a 512×512 PNG base-color texture baked from procedural noise and embedded in the FBX. |
| `zup-centimeters.fbx` | Axis and unit conversion. A 15 cm mushroom exported with Z up and centimeter units. |
| `rock-lods.fbx` | LODs and a collision helper. A rock in three levels, `Rock_LOD0` to `Rock_LOD2`, that group into one part by their suffix, a pebble beside it without LODs, and a convex box, `UCX_Rock`, that starts hidden. |
| `beetle.fbx` | The legs and rig of a modular beetle. One skinned mesh with rigid weights, 13 bones, one 30-frame take, `Walk`, that also moves the Body bone. |
| `beetle-shells.fbx` | Two alternative beetle shells, `ShellRound` and `ShellSpiked`, unrigged and modelled in the rest pose over the Body bone. |
| `beetle-turn.fbx` | Animation only. The beetle's armature with one 40-frame take, `Turn`, and no mesh. |

All files except `zup-centimeters.fbx` use the settings of a typical Blender-to-Unity pipeline:
forward -Z, up Y, apply scale "FBX All", 1 unit = 1 m. Every model stands on the ground at Y = 0, except
the beetle shells, which sit where the Body bone holds them.

`manifest.json` lists the facts importer tests can assert for each file: axes and units, fps, mesh
counts, materials, UVs, shape keys, bones, takes with their frame ranges and key density, and rest-pose
bounds. The script measures these facts from the exported files, by parsing each FBX and by re-importing
it in Blender. It does not copy them from the generator's inputs.

Its `compositions` list gives a model the composition Arcue would keep in that model's review folder. The
beetle's composition attaches both shells to the Body bone, hides `ShellSpiked`, and adds the turn. The web
preview writes it where the core reads it, so `beetle.fbx` opens with its shells and the turn.

## Things importers should expect

- Take names include the armature name: `Armature|Walk`, not `Walk`. Blender's own importer then names
  the action `Armature|Armature|Walk`.
- A clip that spans frames 0 to N has N + 1 keyed frames and lasts N / 30 seconds. Looping clips repeat
  frame 0 at frame N.
- Some key times sit 1 FBX tick before the exact frame time, because the exporter truncates float times
  to integer ticks. Round key times to the nearest frame.
- The blob's take is named after the Blender scene, `Bounce`, because shape-key animation is exported
  through the scene timeline rather than as a per-action take.
- The rigged files also animate the armature object itself, so each take has 252 curves: 9 per bone and
  9 for the armature node.

## Regenerate

Run from the repository root with Blender 5.2:

```sh
blender --background --factory-startup --python-exit-code 1 --python tools/samples/generate.py
```

Add `-- --only crate,blob` to rebuild some files, or `-- --no-export` to only rewrite `manifest.json`.
`--only` still re-measures every file for the manifest.

Two runs produce byte-identical files apart from the FBX creation timestamp. The script swaps the
exporter's per-process salted hash for a fixed one, so object ids stay stable. It also writes only
relative texture paths, so the output does not depend on the checkout directory. Other platforms or
Blender versions may still produce small floating-point differences in remeshing, weights, or the
texture bake.
